# mossplanet リニューアル 画面仕様書（提案・第1版）

## 0. 本書について

mossplanet.com を全面リニューアルするための画面仕様の提案です。Claude Code での実装に入る前の合意用で、2026年11月6〜9日の相談内容を反映しています。

各項目には次の区分を付けています。

| 区分 | 意味 |
| --- | --- |
| 確定 | モスさんが決定した事項 |
| 提案 | 本書で提案している内容。合意すれば確定に移す |
| 要確認 | 事実確認や外部の判断が必要で、現時点では断定できない事項 |

実装時に本書とコードに食い違いが出た場合は、本書を更新してから進めます。前提資料として、プロジェクト内の「既存リポジトリ調査結果」と「決定事項・構成方針」があります。

## 1. コンセプトと目的

コンセプトは「モスが、色んな惑星を作っている」です（確定）。互いにあまり紐づかない活動が宇宙に浮かび、ときどき関連づく――これが「mossplanet」という名前の由来です。大きな母星が1つあるという意味ではありません。

サイトの目的は、優先順に次の3つです（確定）。

1. ブランド・世界観の発信：見ているだけでワクワクする体験を作る。
2. 受注獲得：どのページからでも、依頼の窓口に2クリック以内で届くようにする。
3. 物販への導線：BOOTHへのリンク程度に留める。

次のものは掲載しません（確定）。

- 会社員としての業務実績。掲載するのは個人の活動だけです。
- mireroll。別ブランドなので一切扱いません。

設計の原則は、「骨格は堅実に、表現は世界観に振る」です。骨格とは、URLと1作品1ページの構造のことです。世界観はトップで最も濃くし、一覧ページ、作品ページの順に薄めます。作品ページでは、作品の見やすさを最優先にします。

## 2. 技術構成と運用の前提

既存の構成をそのまま使い、自作で作り直します（確定）。作品の追加は多くても月1回で、作業はPCが中心です。

| 公開 | Netlifyの旧プランの無料枠（帯域100GB/月、ビルド300分/月。2026年11月15日に確認）。GitHubのmainブランチへの反映で自動公開。新プランへは切り替えない | 確定 |
| ドメイン | mossplanet.com（既存）。お名前.comで継続し、更新料は年1,767円、期限は2027年8月11日。DNSはNetlify DNSで管理（apexとwwwがどちらもmossplanet.netlify.appを向く） | 確定 |
| 開発 | Claude Code。作品の追加も「この画像を作品として追加して」と頼む運用を想定 | 確定 |

## 3. サイトマップとURL設計

作品はURLを惑星に依存させず、`/works/<作品ID>/`に置きます（提案）。1つの作品が複数の惑星に所属できるようにするためです。二次創作だけは、エリアごと非公開にできるよう`/fanart/`の下に分けます。

| ページ | URL | 区分 |
| --- | --- | --- |
| トップ（宇宙） | `/` | 確定 |
| 惑星の一覧（5つ） | `/illustration/` `/pixel-art/` `/gamebook/` `/live2d/` `/original/` | 提案 |
| すべての惑星と作品 | `/works/`（ヘッダーの「Works」のリンク先。JavaScriptが動かない環境と旧URLの受け皿） | 確定（2026年11月15日） |
| 作品ページ | `/works/<作品ID>/` | 提案 |
| 二次創作の一覧 | `/fanart/` | 確定 |
| 二次創作のページ | `/fanart/<シリーズID>/`（キャラクター・シリーズ単位で複数枚をまとめる） | 提案 |
| About（モスの星） | `/about/` | 確定 |
| 依頼・問い合わせ（人工衛星） | `/contact/`。送信後は`/contact/thanks/` | 提案 |
| プライバシーポリシー | `/privacy/` | 提案 |
| 英語版 | `/en/` `/en/about/` `/en/contact/` | 提案 |
| 存在しないページ | `404.html`（宇宙で迷子になった演出） | 提案 |

作品IDは英小文字とハイフンで付けます（例：`yorumun-stream-visual`）。日付で始まる旧URL（例：`/works/20240110_yorumun/`）は、`netlify.toml`の転送設定で新しいURLへ301転送します。現行の`netlify.toml`にある全ページ対象の200転送（`/* → /:splat`）は、404ページが正しく返らなくなる恐れがあるので削除します（提案）。

## 4. 共通レイアウト

共通部分はヘッダー、フッター、スマートフォンの下部タブバーの3つです。どれも全ページに表示します（提案）。

**ヘッダー**

- 左にロゴを置きます。横長版（マーク＋文字）を表示し、クリックするとトップへ戻ります。ロゴはPNGしか存在しないため、PNGのまま使います（確定、2026年11月15日）。
- 右に、文字のナビゲーションを置きます。項目は「Works（惑星の一覧を開くメニュー）」「About」「依頼・問い合わせ」、それに言語切替え（JA / EN）です。トップの絵をクリックできない環境や、検索エンジンのための通常のリンクです。
- スマートフォンでは、ロゴをマークだけにして、ナビゲーションは下部のタブバーに移します。
- 色は白、またはロゴ色をごく薄くした色（#e6f5f2）にします。上部に固定表示します。

**フッター**

- SNSのアイコン（X、YouTube、Skeb）とBOOTHへのリンクを置きます。
- プライバシーポリシーへのリンクと、著作権表記（© 年 mossplanet）を置きます。
- 作品ページの白背景を邪魔しないよう、アイコンと小さな文字だけにします。

**スマートフォンのタブバー（画面幅600px未満）**

- 画面下部に固定し、「宇宙（トップ）」「Works」「About」「依頼」の4つを置きます。
- アイコンは16pxのドット絵を2倍で表示します。各惑星や衛星のミニ版を使い回します。
- 「Works」をタップすると惑星の一覧（6つ）が下から開き、どのページからでも別の惑星へ移動できます。

惑星のドット絵アイコンは、「道案内」として使い回します。使う場所は、タブバー、ページ上部の現在地表示（パンくずリスト）、作品ページのタイトル帯です。この使い回しで、作品ページの見やすさを損なわずに、サイト全体の一貫性を保ちます。

## 5. トップページ（宇宙）

トップは、パステル色の宇宙に6つの活動の惑星をグリッド状に浮かべた画面です。PCではほぼスクロールなし、スマートフォンでは1画面強に収めます。

### 5.1 置くもの

| 物体 | 役割 | リンク先 | 区分 |
| --- | --- | --- | --- |
| 活動の惑星 ×6 | イラスト／ピクセルアート／ゲームブック／Live2D／オリジナルキャラクター／二次創作 | 各惑星の一覧ページ | 確定 |
| モスの星 | ロゴの惑星をドット絵にしたもの。作り手本人。顔があるのはこの星だけ | `/about/` | 提案 |
| 人工衛星 | 依頼案内と問い合わせ | `/contact/` | 確定 |
| 流れ星 | 数十秒に1回、画面を横切る。クリックすると最新作品へ移動 | 最新作品 | 提案（任意） |
| 関連線 | 作品を共有している惑星同士を点線で結ぶ。Hugoがビルド時に自動で引く | なし | 提案 |
| NEWの旗 | 公開から30日以内の作品がある惑星に立つ | なし | 提案 |

惑星の名前は絵に描き込まず、HTMLの文字として惑星の下に置きます。検索エンジンが読め、英語版では文字を差し替えるだけで済みます。惑星の並びは少しずつ上下にずらし、整然としたメニューに見えないようにします。

### 5.2 惑星の動き

- 地表は、横長の地表テクスチャを球に巻き付け、280ミリ秒ごとに1ドットずつずらして回転させます（2026年11月16日、本人の指示で140ミリ秒から半分の速さに変更。試作のミニ惑星も同じ）。陰影と縁取りも加えます。縁取りは白（#ffffff）の1ドット、影は惑星の色に深い青（#0a399b）を約4割混ぜた色で、中間の明るさは影の色を市松模様に混ぜて（ディザ）表します。デモと同じ方式です（提案）。
- その場で計算する方式にするか、事前にコマ画像へ書き出す方式にするかは未決定です。初回はその場で計算する方式で作り、JavaScriptが動かない環境では止まった1コマ目を表示します。
- 端末の設定で「視差効果を減らす」がオンの人には、回転、流れ星、星の瞬きをすべて止めます。
- ページを開いたときだけ、惑星が順にふわっと現れる演出を1〜2秒入れます。スクロール量を増やさずに、「宇宙に入っていく」感覚を出すためです。

### 5.3 画面幅と拡大倍率

ドット絵は必ず整数倍で拡大します（確定）。2.5倍のような半端な倍率だと、ドットの大きさが不揃いになり、絵が歪んで見えるためです。惑星は64px四方で描き、画面全体の構図の基準は横320pxとします。

| 画面 | 画面幅 | 並べ方 | 惑星の倍率（表示サイズ） |
| --- | --- | --- | --- |
| スマートフォン | 600px未満 | 2列×3段 | 2倍（128px） |
| タブレット | 600〜1023px | 3列×2段 | 3倍（192px） |
| PC | 1024px以上、画面の高さ900px以上 | 3列×2段 | 4倍（256px） |
| PC（画面の低いノートPC） | 1024px以上、画面の高さ900px未満 | 3列×2段 | 3倍（192px） |

倍率は画面の幅だけでなく高さでも決めます。画面の低いノートPCで4倍にすると、2段目の惑星が画面外に出てしまうためです。背景の星空は繰り返しタイルにして、どの画面幅でも端に余白が出ないようにします。Windowsで表示倍率を125%などにしている環境では、わずかな歪みが出る可能性があります。実機で確認して許容範囲か判断します（要確認）。

### 5.4 惑星の吹き出し（マウスオーバー時）

PCで惑星にマウスを乗せると、その惑星の代表作を小さな吹き出しで見せます（確定）。「この星には何があるのか」が、クリックする前に分かるようにするためです。

**吹き出しの中身（提案）**

| 要素 | 内容 |
| --- | --- |
| 惑星の名前 | 日本語名と英語名（例：ピクセルアート／Pixel Art） |
| ひとこと | 惑星の紹介を1行。全角20字以内 |
| 代表作 | サムネイルを最大3枚、横に並べる。1枚80px四方。正方形に切り抜く |
| 作品数 | 「12 works」のように表示 |
| NEW | 30日以内の新作があれば小さなバッジ |

**代表作の選び方（提案）**

- 作品データの項目`featured_in`に惑星IDを書くと、その惑星の代表作になります。
- 指定が3件未満のときは、新しい作品から順に補います。作品を追加するだけで吹き出しも更新され、手間が増えません。

**表示のルール（提案）**

- マウスを乗せて150ミリ秒後に表示します。マウスが通り過ぎただけで吹き出しがちらつくのを防ぐためです。
- 惑星の上に出し、画面の上端に近いときは下に出します。左右も画面からはみ出さない位置にずらします。
- キーボードのTabキーで惑星を選んだときも同じ吹き出しを出し、Escキーで閉じます。
- 吹き出しは「見るだけ」の表示にし、中のサムネイルはクリックできないようにします。惑星をクリックすると一覧ページへ移動します。サムネイルもクリックできるようにすると、マウスを吹き出しに移す間も開いたままにする制御が必要になり、誤操作も増えるためです。将来の拡張候補とします。
- 吹き出しの枠としっぽはドット絵で作ります（9分割した枠画像を拡大して使う）。中は白背景で、サムネイルはなめらかに表示します。ただし、ピクセルアートの惑星のサムネイルだけは、ぼかさずに拡大します。
- サムネイルはHugoで160pxのWebPを自動生成し、画面が表示された後で読み込みます。最初の表示の速さを落とさないためです。
- 「視差効果を減らす」がオンの人には、吹き出しがその場にただ現れるようにします（ポップする動きを付けない）。

**スマートフォン（マウスオーバーがない端末）の扱い（確定）**

スマートフォンなどマウスオーバーのない端末では、吹き出しを出しません。惑星をタップすると、そのまま一覧ページへ移動します。代表作は、一覧ページの先頭に大きく並べることで補います（第6.1節）。判定は画面幅ではなく、「その端末がマウスオーバーできるか」で行います（CSSの`hover: hover`の判定）。そのため、タッチ操作のタブレットでも吹き出しは出ません。

検討した他の案は採用しませんでした。1回目のタップで吹き出しを出す案は、「タップしたのに移動しない」と感じさせやすいためです。長押しで吹き出しを出す案は、長押しに気づかれにくいためです。

**二次創作の惑星の吹き出し（確定・当面の扱い）**

当面は、二次創作の惑星の吹き出しにサムネイルを出しません。吹き出しには、惑星の名前、ひとこと紹介、作品数だけを表示します。後からサムネイルを出せるよう、惑星の設定（`data/planets.yaml`）に「吹き出しにサムネイルを出すか」の項目（`bubble_thumbs`）を用意し、二次創作だけ`false`にします。

### 5.5 インタラクションの試作（確認用URLだけ）

コンセプトは「モスが色んな惑星を作っていて、ときどき関連づく」です。確認用URLだけで見られる試作ページで比べてから、採用するものを決めます（2026年11月16日作成）。本番のビルドではページ自体を作りません。

- `/lab/a/` 案A「惑星をつくる工房」：空いている場所をクリック（タップ）すると小さな惑星が生まれて漂い、近づくと点線でつながる
- `/lab/b/` 案B「観測ステーション」：惑星に乗ると、ドット絵の枠の吹き出しが出る。中身は、代表作の画像の一部をランダムに切り抜いた横長の小さなバナーと、作品数（数え上がる）。第5.4節の吹き出しの候補（2026年11月16日、本人の指示で手描き風のカードから変更。惑星名とカラーコードは出さない）
- 案Bの試作では、スマートフォンで長押しすると吹き出しが出ます。第5.4節では長押しを採用しないと決めているので、試してみるための仮の動きです。採用するかは試作を触ってから決めます。

## 6. 各ページの仕様

世界観はトップで最も濃くし、一覧ページ、作品ページの順に薄めます。Aboutと人工衛星のページは作品を見る場所ではないので、色を多めに使っても構いません。

### 6.1 惑星の一覧ページ

- 最上部に、惑星のタイトル帯を置きます。背景はその惑星の色を薄めた色で、左に惑星のドット絵（回転する）、右に名前と紹介文を2〜3行。
- その下に、代表作（トップの吹き出しと同じ作品）を大きく並べます。スマートフォンで吹き出しを出さない分の代わりです。
- その下に、全作品をグリッドで並べます。背景は白で、新しい順です。PCは3〜4列、スマートフォンは2列。
- サムネイルの下には、タイトルと年を表示します。
- 他の惑星にも所属している作品には、その惑星の小さなアイコンを添えます。
- 作品が増えてきたら、タグでの絞り込みを追加します。初回は作りません。

### 6.2 作品ページ

最上部のタイトル帯だけ、その惑星のアイコンのデザインと色を踏襲し、その下は白背景にします（確定）。

1. タイトル帯：惑星の色を薄めた背景。左に惑星のアイコン（32pxのドット絵を2倍表示）を置き、クリックするとその惑星の一覧へ戻れます。作品名、制作年、所属する惑星も表示します。
2. メイン画像：白背景の中央に、最大幅1100pxで表示します。クリックすると画面いっぱいに拡大します。ピクセルアートの作品は、ぼかさずに整数倍で拡大します。
3. 作品情報：担当範囲、使用ツール、依頼主（表記してよい場合のみ）、関連リンクを小さな表にまとめます。
4. 本文：制作の狙い、差分画像、メイキング、YouTube動画。画像を先に、説明文を後に置きます。
5. 「この作品が属する惑星」：所属するすべての惑星へのリンクです。別の活動へ移る動線になります。
6. 前後の作品：同じ惑星の中で、前後の作品へ移動するボタンを置きます。ボタンはドット絵の小さな装飾を使っても構いません。
7. 依頼への導線：「このテイストで依頼する」という控えめなリンクを置き、人工衛星のページへ移動します。二次創作のページには置きません。

作品画像のまわりには、装飾を置きません。背景の色が作品の色の見え方を変えてしまうためです。現行のモーダル表示は廃止し、1作品1ページにします。

### 6.3 About（モスの星）

ロゴの色（#54bdb2）をこのページの色にします（確定）。背景はロゴ色を薄めた#e6f5f2、ロゴ色そのものはアイコンや線に使い、文字は濃い色にします（提案）。

- 冒頭：モスの星のドット絵（瞬きなどの小さな動き）、名前（モス／mossgray）、コピー「かわいいに、わくわくをひとさじ」。
- 自己紹介：活動内容と3〜5行の紹介文。
- 6つの惑星の紹介：各惑星へのリンクと、1行の説明。
- SNS：アカウントごとに「何を投稿しているか」を添えて紹介します（例：Xは新作と制作の様子、YouTubeはLive2DとBGM）。
- 頒布物：BOOTH（ドット絵イラスト集 vol.1など）へのリンク。
- 依頼への導線：人工衛星のページへのボタン。
- ロゴはベクターの線画のまま、見出しに使います。ドット絵のモスの星と並べる場合は、使い分けのルール（第7章）に従います。

### 6.4 人工衛星（依頼・問い合わせ）

依頼案内と問い合わせフォームを、1ページにまとめます（提案）。依頼を検討する人が案内を読み終えた位置に、そのままフォームがある形です。

1. 受付状況：「受付中／OPEN」「停止中／CLOSED」の看板を表示します。設定ファイルの1行で切り替えます。
2. できること：キャラクターイラスト、ピクセルアート、Live2Dモデルなどを、作品例へのリンク付きで並べます。
3. 依頼の窓口：基本はSkebへ案内します。料金表をサイトに載せないことで、特定商取引法の表記の問題を避けます（第9章参照）。
4. 進め方：相談から納品までの流れを3〜5段階で示します。「3日以内に返信します」のような返信の目安も書きます。
5. 規約：商用利用の可否、修正の回数、支払いのタイミング、使用範囲を箇条書きで示します。
6. 問い合わせフォーム：Netlify Formsを使い、項目は名前、連絡先、依頼の種類（選択式）、本文の4つだけにします。スパム対策は、人間には見えない入力欄（ハニーポット）だけで、reCAPTCHAは使いません。送信後は、衛星のイラストを添えた完了ページへ移動します。

## 9. SEO・計測・法務・既存作品の移行

### 9.1 SEO

- 各ページに固有のタイトルと説明文（description）を付けます。作品ページは`summary`から作ります。

- サイトマップ（sitemap.xml）には、中身のあるページだけを載せます。現行のサイトでは、作品ごとのURLに中身がない可能性が高いと分かっています。
- 作品ページには、検索エンジン向けの構造化データ（作品名、作者、制作日、画像）と、ページ上部の現在地表示（パンくずリスト）を入れます。

### 9.2 計測

- Googleアナリティクスは使いません（確定、2026年11月15日）。解析を見る予定がないためです。現行サイトにある測定タグ（G-FYDLVHFME8）は、リニューアルで外します。
